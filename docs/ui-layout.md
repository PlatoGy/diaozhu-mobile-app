# 吊主游戏页面布局规范

> 本文件定义吊主游戏前端的页面布局、视觉层级和基础交互。所有页面实现必须以本文件为准。本文件只负责 UI 布局和展示，不改变 `docs/game-rules.md` 中的游戏规则。

## 1. 设计目标

页面采用类似横屏斗地主的四人牌桌布局：

- 手机横屏优先
- 页面全屏显示
- 当前玩家始终位于底部
- 搭档位于顶部
- 上家位于左侧
- 下家位于右侧
- 中央集中展示本墩四名玩家出的牌
- 当前玩家的 52 张手牌必须能够清晰选择和操作
- 视觉风格以传统扑克牌和轻量牌桌为主
- 不采用普通网页式的大量卡片、表单和纵向滚动布局

## 2. 页面方向

### 2.1 横屏优先

主游戏页面仅针对手机横屏进行主要适配。

横屏状态：

- 使用完整牌桌页面
- 页面占满 `100dvw × 100dvh`
- 页面整体不允许纵向滚动
- 手牌区域内部可以滚动或换行

竖屏状态：

- 显示全屏遮罩
- 文案：`请将手机横过来`
- 遮罩中可以显示手机旋转图标
- 竖屏时不展示可操作的游戏桌

### 2.2 安全区

必须考虑：

```css
env(safe-area-inset-top)
env(safe-area-inset-bottom)
env(safe-area-inset-left)
env(safe-area-inset-right)
```

不得让 iPhone 刘海、圆角和底部横条遮挡手牌、操作按钮、玩家头像或右上角菜单按钮。

## 3. 整体页面结构

```text
┌───────────────────────────────────────────────┐
│ 顶部搭档玩家                  右上角更多按钮   │
│                                               │
│ 左侧玩家     中央四人出牌区域       右侧玩家  │
│                                               │
│              阶段提示 / 操作按钮              │
│                                               │
│ 当前玩家信息                                  │
│ 当前玩家手牌（2 排紧密重叠）                 │
└───────────────────────────────────────────────┘
```

页面采用相对座位，而不是固定 Seat 的绝对方向。

## 4. 相对座位

无论当前玩家实际是哪个 Seat，页面方向始终为：

```text
当前玩家：底部
搭档：顶部
上家：左侧
下家：右侧
```

固定出牌座位顺序：

```text
Seat 0 → Seat 1 → Seat 2 → Seat 3 → Seat 0
```

实现纯函数：

```ts
getRelativeTablePosition(
  viewerSeat: Seat,
  targetSeat: Seat
): "bottom" | "top" | "left" | "right"
```

约定：

```text
bottom = viewerSeat
top = partnerSeat
left = previousSeat
right = nextSeat
```

## 5. 背景和整体风格

背景暂不限定蓝色或绿色，但必须符合牌桌效果。

要求：

- 使用纯色或非常轻微的纹理
- 中央区域保持干净
- 扑克牌必须与背景有足够对比
- 不使用复杂背景图片
- 不使用赌场筹码、老虎机、金币雨等装饰
- 不使用大面积玻璃拟态卡片

推荐第一版使用深蓝色或深绿色牌桌背景，并将主题颜色定义为 CSS 变量，方便后续切换。

视觉优先级：

1. 当前玩家手牌
2. 中央本墩出牌
3. 当前操作按钮
4. 当前轮到的玩家
5. 庄家、主花色和得分
6. 头像、昵称和剩余牌数
7. 右上角更多按钮

## 6. 玩家区域

每名玩家均显示：

- 圆形头像
- 随机昵称
- 红队或蓝队标记
- 庄家标记
- 当前轮到标记
- 剩余手牌张数
- 准备状态
- 必要时显示网络连接状态

头像和昵称暂时随机生成，不提供用户配置入口。

### 6.1 队伍颜色

两组搭档关系使用红蓝区分。

例如：

```text
Seat 0 + Seat 2：红队
Seat 1 + Seat 3：蓝队
```

要求：

- 当前玩家和搭档使用同一队伍颜色
- 两名对手使用另一队伍颜色
- 队伍颜色用于头像边框、昵称旁标记或小色条
- 不要使用大面积红蓝背景
- 除红蓝外，同时显示“红队”“蓝队”或队伍图标，避免只依赖颜色传达信息

### 6.2 庄家标记

庄家头像旁显示 `庄`，建议使用小型圆形或盾牌状徽标。

### 6.3 当前轮到标记

当前轮到的玩家区域应有明显提示，例如头像外圈高亮、头像旁显示倒计时，或昵称附近显示“出牌中”。不要让高亮影响布局尺寸。

## 7. 顶部搭档区域

搭档位于页面顶部中央。

显示：

- 圆形头像
- 昵称
- 红队或蓝队标记
- 庄家标记
- 剩余牌数
- 一叠牌背

牌背只作为视觉牌堆，不按实际剩余牌数渲染几十张 DOM。可以用 2～4 张轻微错位的牌背，并在旁边显示 `剩余 38 张`。

搭档当前出的牌不放在牌背区域内，而是放在中央出牌区域的顶部槽位。

## 8. 左右玩家区域

上家位于左侧，下家位于右侧。

每侧显示：

- 头像
- 昵称
- 队伍颜色
- 庄家标记
- 剩余牌数
- 小型牌背堆

左右玩家出的牌应紧挨头像并向中央延伸：

- 左侧玩家出牌槽位于头像右侧
- 右侧玩家出牌槽位于头像左侧

## 9. 当前玩家区域

当前玩家位于底部。

显示：

- 左下方或手牌左侧显示头像
- 昵称
- 红队或蓝队标记
- 庄家标记
- 当前手牌数量
- 当前组合资格的必要提示
- 手牌区域
- 手牌上方中央的操作按钮

当前玩家不需要显示牌背。

## 10. 中央四人出牌区域

### 10.1 整体形状

页面中间偏上的位置设置一个横向长方形出牌区域。

建议比例：

```text
宽度：页面宽度的 52%～64%
高度：页面高度的 24%～32%
```

区域使用轻微半透明底色或细边框，不使用厚重卡片阴影。

### 10.2 固定四个槽位

```text
              搭档出牌

上家出牌                    下家出牌

              自己出牌
```

每名玩家的槽位始终固定，并按当前玩家视角重新计算。

### 10.3 正面显示

所有玩家已经出的牌，对所有玩家都正面展示。

每名玩家一手最多出 4 张，因此每个槽位最多容纳 1～4 张牌。牌可以轻微横向重叠，但必须看清每张牌的点数、花色和大小王。

### 10.4 槽位标记

每个槽位可显示小型标签：

```text
自己
搭档
上家
下家
```

也可以显示玩家昵称。

若牌型为散牌，可显示 `散牌`；对子、三个和四个可显示对应牌型标签。

## 11. 一墩结束展示

服务端完成一墩结算后：

1. 中央区域继续保留这一墩四名玩家出的牌
2. 显示赢家头像或昵称
3. 显示 `XXX 赢得本墩`
4. 保留 1000ms
5. 随后清除中央出牌区
6. 展示下一墩的空槽位或新出牌

要求：

- 不需要玩家点击“收牌”
- 不做牌飞向赢家的动画
- 不重放已经看过的历史墩
- 最后一墩也先保留 1 秒，再展示本局结算面板

## 12. 操作按钮区域

操作按钮位于当前玩家手牌上方中央，不放在右下角。

可能出现的按钮：

```text
准备
取消准备
我坐庄
摔 2
进贡
回贡
拿底牌
扣底
出单张
出对子
按散牌出
出三个
出四个
下一局
```

布局要求：

- 主要按钮水平居中
- 最多同时显示 2～3 个主要操作
- 按钮高度适合手机横屏点击
- 主要按钮宽度约 100～150px
- 禁用按钮必须有明显状态
- 错误提示显示在按钮上方或旁边，不使用浏览器 alert

扣底、进贡、回贡时显示类似 `已选择 3 / 8` 或 `请选择 2 张牌`。

## 13. 当前玩家手牌

### 13.1 双排布局

因为当前玩家通常持有 52 张牌，拿底后最多持有 60 张牌，因此不得强制单排显示。

规则：

- 常规 52 张：固定使用 2 排
- 拿底后 60 张：仍固定使用 2 排
- 不再自动切换到 3 排
- 根据可用宽度动态计算牌宽与横向重叠距离

### 13.2 手牌紧密重叠

同一排采用明显横向重叠：

- 大部分牌只露出左上角的点数和花色
- 每排最后一张显示完整牌面
- 同花色同点数的牌应相邻
- 相邻牌的可点击区域仍须可用

建议重叠偏移根据屏幕宽度动态计算：

```text
14px ～ 22px
```

### 13.3 行间距离

多排之间需留出足够空间，确保：

- 第一排牌被选中上移后不会完全遮挡上一排
- 每张牌左上角点数仍可识别
- 玩家能够准确点击某一张实体牌

后一排可以轻微覆盖前一排底部，但不得遮挡点数区域。

### 13.4 选中效果

点击手牌后：

- 牌向上移动约 14～20px
- 增加清晰边框或阴影
- 再次点击取消
- 使用 `card.id` 记录选中状态
- 不使用数组索引

Action 成功后清空选中状态；Action 失败时保留选择。

## 14. 传统扑克牌样式

每张牌使用传统扑克牌风格：

- 白色或米白色牌面
- 圆角矩形
- 浅灰边框
- 轻微阴影
- 黑桃和梅花为黑色
- 红桃和方块为红色
- 左上角显示点数和花色
- 右下角可以倒置显示点数和花色
- 中央显示较大的花色
- 大王、小王使用 Joker 或“大王 / 小王”
- 不依赖外部在线图片

牌组件支持：

```ts
selected
disabled
faceDown
compact
overlapped
```

桌面出牌使用较大尺寸，当前玩家手牌使用较小紧凑尺寸，头像旁牌背使用 compact 牌背。

## 15. 顶部信息栏

页面顶部显示：

- 当前局数
- 当前阶段
- 庄家
- 主花色
- 闲家分数
- WebSocket 连接状态

信息栏应紧凑，不能占据过多高度。

## 16. 右上角更多按钮

右上角仅保留一个 `⋯` 按钮。

当前阶段不要求实现完整菜单内容。可以预留未来功能：

- 游戏规则
- 声音设置
- 退出房间
- 全屏
- 网络诊断

未实现的菜单项可以隐藏，不显示不可用的假按钮。

## 17. 各阶段布局

### waiting_for_players

中央区域可替换为四人准备面板，显示四个玩家头像、昵称、队伍颜色、是否进入和是否准备。当前玩家显示“准备”或“取消准备”。四人全部准备后服务端自动开始。

### choosing_dealer

牌桌布局继续保留。中央显示“红队选择庄家”或“蓝队选择庄家”。获胜方两名玩家显示“我坐庄”，其他玩家显示等待状态。

### dealing / final_trump_bidding

底部直接显示完整手牌，不播放发牌动画。中央显示当前最高摔 2：玩家、花色、数量和对应牌面。摔出的 2 继续保留在手牌中，最高摔 2 公开到主花色锁定为止。

### tribute

有进贡任务的玩家：高亮最大牌候选，显示数量、接收者和“进贡”按钮。

有回贡任务的玩家：高亮合法回贡牌，显示“回贡”按钮。

其他玩家显示等待。

### taking_bottom

庄家显示“拿底牌”，其他玩家显示“等待庄家拿底”。

### burying_bottom

庄家显示 60 张牌并继续使用 2 排密集重叠布局。显示 `已选择 0 / 8`，选择 8 张后启用“扣底”。

### playing

中央显示固定四槽位出牌区域。当前出牌玩家头像高亮。

轮到当前玩家时，可以选牌并显示合法 declaredType 按钮；未轮到时，只能查看手牌，显示 `等待 XXX 出牌`。

### round_finished

先展示最后一墩赢家 1 秒，再显示本局结算：获胜队伍、闲家分数、贡数、最后一墩赢家、底牌分和倍数。所有玩家显示“下一局”。

## 18. 响应式尺寸建议

常见手机横屏：

```text
宽度：667px ～ 932px
高度：320px ～ 430px
```

建议：

- 顶部信息栏高度：28～36px
- 顶部玩家区域高度：55～75px
- 中央出牌区高度：90～125px
- 操作按钮区高度：40～55px
- 手牌区域占剩余主要空间
- 左右玩家区域宽度：80～120px

不得依赖单一固定分辨率。

## 19. 组件拆分建议

```text
GameTable
TopStatusBar
PlayerBadge
PlayerCardBackStack
TeamBadge
CentralTrickArea
TrickPlaySlot
ActionBar
PlayerHand
HandRow
PlayingCard
PortraitOrientationOverlay
MoreMenuButton
RoundResultPanel
ConnectionStatus
```

不得把所有 UI 写入一个巨大页面组件。

## 20. 明确禁止

不要实现为：

- 普通网页纵向卡片列表
- 四个玩家信息都挤在顶部
- 当前玩家手牌单排无限横向滚动
- 中央只显示最后一个玩家出的牌
- 已出的牌使用牌背
- 每张手牌完全不重叠导致无法容纳
- 操作按钮固定在右下角并遮挡手牌
- 使用数组 index 作为牌的 key
- 将其他玩家手牌发送到前端后再隐藏
- 页面整体出现纵向滚动条
- 竖屏下强行压缩游戏桌

## 21. 验收标准

第一版完成后必须满足：

1. 四个玩家均位于正确相对方向。
2. 当前玩家和搭档队伍颜色一致。
3. 红蓝两队一眼可区分。
4. 顶部玩家显示牌背和剩余牌数。
5. 左右玩家的出牌靠近头像。
6. 中央长方形区域可同时显示四家各 1～4 张牌。
7. 所有已出的牌正面显示。
8. 52 张手牌可在手机横屏中用 2 排操作。
9. 60 张牌仍可用 2 排密集重叠操作。
10. 手牌重叠后仍能看清点数和花色。
11. 点击牌可准确选中和取消。
12. 操作按钮位于手牌上方中央。
13. 一墩结束后保留 1 秒并显示赢家。
14. 页面没有整体纵向滚动。
15. 竖屏时显示旋转提示。
16. 右上角只保留更多按钮。
17. 页面整体呈现为游戏牌桌，而不是普通管理后台。
